# 管理介面操作說明

服務：`admin_api`（`0.0.0.0:33691`），無需登入。導覽列固定五個項目：
抓取狀態、原始 HTML、商品搜尋、合併商品、手動合併。

## 抓取狀態（首頁 `/`）

最近 20 筆抓取/匯入紀錄，欄位：估價時間、類型（`scheduled`/`manual`/
`import`）、狀態（`success`/`partial`/`failed`，見
[`docs/database-schema.md`](database-schema.md#status-狀態機)）、商品總數、
新商品數、下架數、漲價數、降價數、錯誤訊息。

「手動執行抓取」按鈕（`POST /scrape`）會立即觸發一次抓取，跟排程共用同一組
併發鎖（見 [`docs/architecture.md`](architecture.md#併發控制)），若排程剛好
正在執行，本次手動抓取會被跳過（`ScrapeSkipped`），畫面上不會顯示錯誤，
只是這次點擊沒有效果，可從「抓取狀態」列表確認是否真的有新紀錄產生。

## 原始 HTML 封存（`/html-archive`）

列出所有保留有原始 HTML 檔案的抓取紀錄（`GET /html-archive`），點擊估價
時間可檢視當次抓取保存下來的完整 HTML 內容（`GET /html-archive/{id}`，
以 cp950/Big5 解碼後顯示）。用途：解析失敗或懷疑資料有誤時，回頭比對原站
當時實際的 HTML 結構。

## 商品搜尋 / 詳細編輯頁（`/products`）

### 列表頁

- 搜尋輸入框（AND 語意，見 [`docs/search-semantics.md`](search-semantics.md)）
  + 分類篩選 + 上架狀態篩選。
- 欄位：ID、商品名稱（可點擊進入詳細頁）、品牌、型號、目前價格、是否在售、
  建立時間；欄寬可手動拖曳調整。
- 分頁機制與公開搜尋頁一致：數字頁碼（含省略號）、可指定每頁筆數
  （10/20/50/100/500/1000/全部）、輸入頁碼後按 Enter 直接跳頁、切換每頁
  筆數時保留原本捲動位置。
- 頁尾提示「複製要合併的商品 ID，到合併商品頁面操作」——連到手動合併頁。

### 詳細頁（`GET /products/{id}`）

預設唯讀顯示完整欄位：ID、分類（原始名稱，見下方說明）、商品名稱、品牌、
型號、原始狀態、目前價格、是否在售、最後一次出現時間、建立時間。

> **分類欄位刻意顯示 `Category.name`（原始名稱），不是 `Category.label`
> （自訂顯示名稱）**——這一頁是用來核對/編輯商品真實分類歸屬的，跟公開
> 搜尋頁/管理搜尋頁列表的分類篩選下拉（仍顯示自訂顯示名稱）刻意不同。

點擊「編輯」切換成可編輯表單（純前端顯示切換，不重新載入頁面）：

| 欄位 | 控制項 |
|---|---|
| 商品名稱 | 文字輸入框 |
| 分類 | 下拉選單（顯示原始名稱），最後一個選項是「+ 新增類別」 |
| 子分類 | 下拉選單，選項依所選分類動態重建 |
| 品牌 / 型號 / 原始狀態 | 文字輸入框（可留空） |
| 目前價格 | 數字輸入框 |
| 是否在售 | 下拉選單（在售／已下架） |

「儲存」送出 `POST /products/{id}`，成功後導回詳細頁並顯示「已儲存」；
「取消」放棄編輯、切回唯讀顯示（不送出任何請求）。

伺服端驗證：子分類必須屬於所選分類（否則 `400`）；已被合併掉的商品
（`merged_into_id` 不為空）一律拒絕編輯（`400`），畫面上這種商品也不會顯示
「編輯」按鈕，改為顯示「此商品已合併至 #X ...，不可編輯」並連到合併後的
目標商品。

### 新增分類（分類下拉選單內）

選擇「+ 新增類別」會跳出瀏覽器輸入框要求輸入新分類名稱，確定後立即呼叫
`POST /categories`（不需離開頁面）：

- 名稱重複（`categories.name` 有 unique 限制）→ 顯示錯誤訊息，選單還原成
  先前選取的分類。
- 成功 → 分類下拉選單即時插入新選項並自動選取；同時依現有資料庫慣例自動
  建立一筆名稱為空字串的子分類（代表「分類本身」，跟原價屋大多數分類的
  既有資料型態一致，見 [`docs/database-schema.md`](database-schema.md#subcategories)），
  子分類下拉選單也會即時更新並選取這筆新子分類。

## 合併商品（相似度建議，`/similarity-hints`）

系統依名稱相似度自動找出候選重複商品（演算法見
[`docs/architecture.md`](architecture.md#相似度合併機制)）。

「重新計算相似度候選」（`POST /similarity-hints/refresh`）會重新掃描全部
商品產生新候選；**這是同分類商品數的 O(n²) 運算，商品基數大時可能耗時數
分鐘且會使 CPU 使用率大幅上升**，執行期間頁面會等待回應，請避免頻繁重複
觸發。

每組候選以卡片呈現：商品 A / 商品 B 上下並排（已下架的一方會標註
「（已下架）」），旁邊顯示相似度百分比。操作方式：

- 勾選任意組候選，點「合併」（`POST /similarity-hints/batch-merge`）或
  「忽略」（`POST /similarity-hints/batch-dismiss`，標記為不是同一商品，
  之後不再出現在候選列表）。
- 「合併下列所有項目」會先跳出確認視窗（顯示目前候選組數），確認後**自動
  勾選全部候選並送出合併**，不需要逐一手動勾選。
- 合併方向（誰是保留下來的目標商品）由 `choose_merge_direction()` 自動
  決定，不需人工指定，規則見
  [`docs/architecture.md`](architecture.md#合併方向決策choose_merge_direction)。
- 合併完成後會顯示「已合併 N 組，略過 M 組」（略過通常是候選商品在此之前
  已被其他操作合併掉）。

## 手動合併（`/merge`）

不依賴相似度分數，直接搜尋並手動指定要合併的兩個商品，適合系統相似度沒抓
到、但人工判斷確定是同一商品的情況。

- 搜尋輸入框（`GET /products/search-json`，AND 語意、無結果筆數上限）+
  下拉結果清單，可用上下鍵選擇、Enter 加入，最多加入 2 個商品，以「chip」
  形式條列顯示（一個商品一行）。
- 每個 chip 左側有一個「主要」單選按鈕，用來標記哪個商品是合併後保留的
  目標商品（target）；另一個自動成為來源（source）。
- 「合併」送出 `POST /merge`（`source_id`/`target_id`）。前端會擋掉未選滿
  兩個商品、或沒有標記主要商品的情況；伺服端額外擋掉來源與目標相同、
  來源或目標已經是別次合併的來源/目標等狀態（`MergeError`，訊息顯示在
  頁面上）。

頁面下方「合併紀錄」列出所有人工與批次相似度合併的紀錄（最多 200 筆，
含時間、來源、目標、狀態），尚未 Undo 的紀錄可點擊「Undo」
（`POST /merge/{id}/undo`）復原——把商品名稱移回來源商品、清除
`merged_into_id`。Undo 有以下限制（`MergeError` 訊息會顯示在頁面上）：
找不到合併紀錄、此合併已被 Undo 過、或這批被搬動的名稱之後又被更新的一次
合併影響（此時須先 Undo 較新的那筆）。
