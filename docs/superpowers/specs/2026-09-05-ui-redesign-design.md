# 前端 UI 改版設計（數據終端方向）

- 分支：`feature/ui-redesign`
- 範圍：`public_api` 公開查詢頁與 `admin_api` 管理介面，兩者共用底層 token，
  但視覺調性各自不同。
- 性質：可重新編排版面與互動，並新增必要的前端功能；不改動既有路由與
  後端語意（唯一的後端新增是 sparkline 的批次價格 API）。

## 設計方向

公開頁走**數據終端**：致敬原價屋估價單本身的高密度表格文化，但用專業排版
重做。細線、無外框、等寬數字、只有漲跌上色，每列附 30 日迷你走勢，讓人一
眼看出「這東西正在漲還是跌」。它應該讀起來像財經終端，不像購物網站。

管理介面沿用同一組 token，但更緊湊、資訊密度更高，狀態色（成功／失敗／
部分成功）是它唯一額外的色彩預算。它是工具，不是展示品。

## Color

顏色只承載訊息，不做裝飾。紅代表漲、綠代表跌（台股慣例，與美股相反），
銅金代表可互動與當前狀態，其餘一切由中性灰承擔。

明亮主題（估價單紙）：

| token | 值 | 用途 |
|---|---|---|
| `--bg` | `#ECEDEF` | 頁面底，冷灰白 |
| `--surface` | `#FFFFFF` | 表格與卡片 |
| `--ink` | `#14161A` | 主要文字 |
| `--muted` | `#6B7076` | 次要文字 |
| `--line` | `#DCDDE0` | 分隔線 |
| `--accent` | `#8A6A1E` | 連結、焦點、當前狀態（銅） |
| `--up` | `#C0362C` | 漲 |
| `--down` | `#1B7A4B` | 跌 |

暗色主題（夜裡的螢幕）：

| token | 值 | 用途 |
|---|---|---|
| `--bg` | `#12161F` | 靛藍黑，帶明確藍調而非純黑 |
| `--surface` | `#181D28` | |
| `--ink` | `#E6E8EC` | |
| `--muted` | `#8B93A1` | |
| `--line` | `#262D3A` | |
| `--accent` | `#C9A227` | 金手指黃 |

預設跟隨作業系統 `prefers-color-scheme`，header 可手動切換，選擇存在
`localStorage`。

## Type

- **IBM Plex Mono**（Regular 400 / SemiBold 600，SIL OFL，self-host 於
  `static/fonts/`，兩檔共 92 KB）用於價格、數量、日期、型號等所有需要
  對齊的英數字串。它承擔這個設計的個性：估價單的工程氣質。
- **中文與敘述文字**用系統字體堆疊（`PingFang TC` / `Noto Sans TC` /
  `Microsoft JhengHei`）。不 self-host 繁中字體：單一字重就要 3–5 MB，
  subset 又會在罕見商品名上掉字，而原價屋的商品名什麼字都有。
- 等寬字只用於數字與型號的功能性對齊，不拿來當小標籤的裝飾。

## Layout

公開搜尋頁的第一眼是搜尋列與**今日異動摘要**，資料直接取自最新一筆
`scrape_snapshots`（漲、跌、新增、下架四個現成欄位，零額外查詢成本）。
價格追蹤最有代表性的一刻就是「今天有什麼變便宜了」，這比一個大數字配
漸層背景有內容。

```
原價屋歷史價格          搜尋   比較 2   ☾
──────────────────────────────────────────────
 [ 搜尋商品名稱                     ]
 09-04 23:00 抓取   12,438 項   ▲ 87 漲   ▼ 143 跌   + 12 新增
──────────────────────────────────────────────
 商品                     30 日      價格     漲跌
 微星 MAG B850 TOMAHAWK  ▁▂▃▅▇▆▄▃   6,990   ▲  +200
 技嘉 RTX 5070 GAMING    ▇▆▅▃▂▁▁▂  22,900   ▼  −800
```

文字左對齊，數字右對齊（財務慣例）。分隔線只在需要分組時出現，不是每列
都畫。圓角一律 2px：不是 broadsheet 式的全直角，也不是 SaaS 卡片的大圓角。

商品詳細頁以價格為主角：現價用大尺寸等寬字，歷史最低／最高與漲跌貼在它
下方，走勢圖佔滿內容寬度。

## Sparkline 的資料路徑

搜尋結果每列要顯示 30 日走勢，但資料庫有 19,194 個商品與 2,990,579 筆
價格歷史，而搜尋頁的每頁筆數可以選到「全部顯示」。因此：

- 新增 `GET /api/products/sparklines?ids=...&days=30`，一次批次回傳多個
  商品的取樣價格點（每商品最多 32 點），單一 SQL 查詢完成。
- 前端在表格渲染完成後才非同步取用，不阻塞首次繪製。
- 每頁筆數超過 100 時整欄降級隱藏 —— 一次要 500 條走勢既無法閱讀，也不
  值得那個查詢成本。
- 走勢圖是自己畫的 inline SVG（約 40 行原生 JS），不引入圖表函式庫。

## 檔案架構

```
src/coolpc/web/static/
  css/tokens.css    兩個 app 共用：色彩、字級、間距
  css/base.css      共用元素：表格、表單、按鈕、分頁、header
  css/public.css    公開頁專用
  css/admin.css     管理頁專用
  fonts/*.woff2     IBM Plex Mono
  js/sparkline.js   無依賴的迷你走勢圖
  js/theme.js       明暗切換與記憶
```

兩個 `app.py` 各自 `mount("/static", ...)` 指向同一個實體目錄。不引入
Tailwind 或任何建置流程 —— 那會牴觸專案「刻意不使用前端框架」的原則，
也讓部署多一個 node 依賴。

## 品質底線

響應式到手機、鍵盤焦點可見、`prefers-reduced-motion` 生效、色彩對比符合
WCAG AA。動效只用在回應使用者操作的地方（展開、切換主題），沒有捲動進場
動畫。
